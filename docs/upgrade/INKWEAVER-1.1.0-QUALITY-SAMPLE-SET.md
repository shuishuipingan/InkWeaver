# InkWeaver 1.1.0 固定质量样本集

版本：`1`  
用途：1.1.0 开发与发布前验收  
隐私：全部内容为仓库内生成的合成文本，不包含用户作品、API key 或外部授权作品。

## 样本入口

固定样本由 [scripts/quality-fixtures.ts](../../scripts/quality-fixtures.ts)
提供，测试入口为
[scripts/__tests__/quality-fixtures.test.ts](../../scripts/__tests__/quality-fixtures.test.ts)。

运行：

```text
pnpm exec vitest run scripts/__tests__/quality-fixtures.test.ts
```

当前 fixture 测试必须证明：

- 24 对章节样本固定为 6 类，每类 4 对：即时承接、跨日、换地点、换视角、倒叙、延后兑现。
- 每对样本有前章文本、后章文本和评阅者应观察的信号；评阅者评分时只看到匿名样本 ID。
- 长篇样本固定生成 100 章，包含第 12 章取得钥匙、第 18 章转交、第 30 章受伤、第 40 章恢复、第 55 章得知秘密和第 70 章读者知识确认等已知状态转移。
- 样本生成是确定性的，可通过 `hashQualityFixture(buildLongFormQualityFixture())` 得到稳定 SHA-256；输入变化必须导致哈希变化。

## 章节对盲评协议

每个 `ChapterPairQualityCase` 需要生成两份匿名结果：开发前基线和开发后结果。模型、模型参数、章节蓝图、前文输入、最大输出预算、提示词版本和实际 token 用量必须一并记录。评阅者不能从文件名判断哪一份是新版。

两名评阅者分别对以下维度打 1–5 分，并保留原文理由：

1. 现场和动作承接是否自然；
2. 时间、地点和视角切换是否交代充分；
3. 情绪及人物选择是否延续；
4. 已知/未知信息是否越界；
5. 重复背景是否为必要复沓；
6. 延后兑现是否被错误判定为遗忘。

路线图中的发布门槛仍然适用：新版偏好率至少 70%，自然承接平均分提升至少 0.5/5，事实正确性不得下降；有意转场/悬念被误报为必须修稿的比例不超过 10%。这些结果尚未在本仓库声明为通过。

## 100 章长篇验证协议

长篇 fixture 的事实查询必须覆盖：

- 第 12 章取得钥匙、第 18 章转交后的所有权差异；
- 第 30 章受伤与第 40 章恢复之间的有效范围；
- 第 55 章角色知情与第 70 章读者知情的分离；
- 早期规则在后期上下文中的召回、输入预算、省略原因和延迟；
- 任意来源章节修改后，交接、事实、人物候选、伏笔和检索投影的过期标记与可恢复重建。

每次长篇运行需保存：源码 SHA、fixture SHA、模型/提示词版本、查询章节、纳入/省略的上下文层、延迟、token 用量、误报/漏报以及失败样例。不得只记录“模型返回成功”。
