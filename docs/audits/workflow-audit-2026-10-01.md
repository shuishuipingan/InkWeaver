# 工作流审计 — 2026-10-01

基线：`68fd733`（桌面版 1.3.8）。本轮沿工作流工厂、统一执行器、生成运行时、SQLite 提交、恢复入口和定稿后处理追踪数据与错误边界。

## 已确认并修复的问题

| 范围 | 触发条件与原问题 | 修复与验证场景 |
| --- | --- | --- |
| 批量恢复 | 已保存任一章节后失败，恢复从首章开始并被已有草稿拒绝 | 保存 ID 与 SHA-256；只采用原任务草稿，跳过已完成章节，继续未完成定稿；测试缺失、改动和不属于任务的草稿 |
| 定稿恢复 | 原定稿修订号非零，关闭/重新打开标签后恢复使用不同修订号 | 在提交前保存并重用原修订号；测试修订号 7、关闭标签及重新打开为修订号 19 的恢复 |
| 保存后取消 | SQLite 保存已提交，取消检查却把结果当未保存清空 | 成功响应后先保存路径、正文与恢复身份，再检查取消；延迟保存响应回归用例 |
| 单章恢复 | 草稿已经保存，恢复仍重新调用模型 | 按 ID、章节、最新版本与正文散列核验，只恢复已保存内容 |
| 架构恢复 | 第一阶段已成功，后续阶段失败，恢复重写成功阶段 | 恢复只选未完成阶段，使用数据库已有架构并更新原收据 |
| 蓝图恢复 | 蓝图原子提交后，角色同步失败或取消 | 保存持久化同步 operation ID；只重试 SQLite 中的同步操作，不重复请求或提交蓝图 |
| 定稿补修 | 关键后处理仍失败，补修却显示完成；交接步骤消失 | 检查返回步骤状态；完整生成来源绑定的交接步骤，失败阻止完成 |
| 状态顺序 | 同秒创建两次后处理跑批，最新查询可选中早期结果 | `created_at DESC, rowid DESC`；同秒成功/失败记录回归 |
| 角色状态 | 修复旧章将状态倒退，或覆盖同章人工修正 | 按生效章节与来源保护当前状态；真实定稿来源测试同时确认后续章节可继续推进 |
| 拆批异常 | 子请求取消/预算/供应商失败被原始合同错误替代 | 保留真实子异常与物理尝试收据；仅在子合同同样无效时保留原始诊断 |
| 输出预算 | 大输出模型使小型结构化请求提前耗尽操作总预算 | 结构化/角色请求遵守步骤意图上限；测试预算策略与小批次边界 |
| 模型选择 | 蓝图生成忽略工作流已选模型，转而使用全局默认 | 将冻结模型 ID 传给生成运行时；运行时创建参数回归 |
| 取消执行器 | 持久化取消回调同步抛错，暂停等待不被释放 | 同步与异步回调异常均记录，继续完成取消边界 |
| 恢复存储 | 任一损坏记录导致所有记录丢失，损坏根阻断新保存 | 逐条 schema 校验与隔离；损坏根可重建，新收据正常保存 |

## 验证范围

- 新增回归先复现失败，再验证修复；实际 SQLite 仓储测试覆盖状态与后处理来源。
- 完整单元测试、浏览器用例、类型、lint、i18n、运行日志覆盖与生产构建纳入最终核验。
- 恢复始终要求相同项目 lease；旧版本缺少来源身份的收据不会自动采用已有草稿。此限制用于避免恢复旧结果覆盖当前项目。
- 模型边界使用可控响应和异常测试；未向作者配置的真实模型网关发送收费请求。模型服务当时的余额、可用性和实际生成质量不属于这些模拟测试证明的范围。
- 发布沿用仓库资格与 promotion 门禁，实际平台结果以对应 GitHub Actions 收据为准。
