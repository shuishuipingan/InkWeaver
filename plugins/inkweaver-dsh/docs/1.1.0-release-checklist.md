# InkWeaver DSH 1.1.0 分发清单

状态：开发线准备文档，不是已发布版本声明。  
适用包：`@shuishuipingan/inkweaver-dsh`  
目标版本：`1.1.0`  
官方宿主兼容基线：`@deepseek-ai/dsh 0.1.5-rc.1`

## 冻结前提

只有以下条件全部成立，才允许把插件 `package.json` 从当前开发版本改为
`1.1.0`：

1. 1.1.0 追踪表的 38 项需求和 12 条端到端旅程完成评阅；
2. DSH qualification 在冻结源码 SHA 上重新执行并生成 `passed` receipt；
3. `package.json` 与 `plugins/inkweaver-dsh/package.json` 同时冻结到 `1.1.0`；
4. README、兼容矩阵、CHANGELOG 和 GitHub 分发收据都指向同一源码 SHA；
5. npm 发布权限、包名和公开 topic 元数据已经由发布负责人确认。

当前开发线仍是桌面 `0.9.2`、插件 `0.1.0`，不得把下面的命令结果解读成
正式发布。

## 冻结后的执行顺序

在仓库根目录：

```text
node scripts/release-version-sync.mjs --expected-version 1.1.0
pnpm run typecheck
pnpm test -- --maxWorkers=1
```

在插件目录：

```text
pnpm install --frozen-lockfile
pnpm run typecheck
pnpm run build
pnpm pack --pack-destination .runtime/release-artifacts
```

然后使用与源码 SHA 绑定的 Harness checkout 执行完整 qualification：

```text
node plugins/inkweaver-dsh/scripts/qualify-release.mjs \
  --harness-root <clean-official-harness-checkout>
```

qualification 必须回读并保存：

- tarball 文件名、字节数和 SHA-256；
- 包名、版本、preset/Host 身份和 39 项包内容；
- profile add/remove/reinstall 结果；
- `inkweaver-v2` roster/mount 和 exactly-two-tool 清单；
- Proposal 应用、重启、重装和 schema 5 持久化读回；
- 三次真实 Chrome Web journey 与截图/几何数据；
- 官方 Harness commit、插件源码 commit 和锁文件哈希。

## npm 与 GitHub 发布

qualification receipt 通过后才允许：

```text
pnpm publish --access public
```

发布后必须用 npm registry 回读包名、版本和 tarball SHA，并把同一 SHA
写入 `docs/upgrade/DSH-MANUAL-PROFILE-RECEIPT.md` 和
`docs/upgrade/GITHUB-DISTRIBUTION-RECEIPT.md`。历史包名
`@ethanyoq/dsh-ai-novel-writer` 不得重新出现在 manifest、README 或发布命令中。

`@linxin666/dsh-web-all@0.3.20` 只是外部 DSH Web 宿主依赖，不得打入
InkWeaver tarball，也不得被描述为本项目插件。

GitHub `dsh-plugin` topic 的元数据和实际主题页索引是两项独立证据。正式
Release 创建后必须重新回读仓库 topics、Release 资产和主题页；索引延迟时
应在 CHANGELOG/分发收据中明确记录，不得宣称“已可见”。

## 回滚

若 npm tarball、qualification receipt、GitHub Release 资产或 topic 回读
任何一项不一致，停止公开发布，保留当前开发分支和 receipt，撤回未完成的
Release 草稿；不要通过重新打包或改写哈希来掩盖不一致。
